## A. Code

### 1. Wartende Aussaat speichert mitten in einem Restore — **umsetzen** — ✅ `b270bab`
- **Stelle:** `LauncherState.kt:132-137` (Aussaat im `refresh`-Hand-off).
- **Neu durch** `13208c0`: Auf `main` gab es Aussaat nur beim ersten Laden, vor dem kein
  `~`-Befehl laufen kann. Jetzt läuft sie in jedem späteren Hand-off und ruft `mutated()` →
  `save()` ohne `CommandGate`-Prüfung — als einzige Konfig-Änderung neben `forget` ohne
  `EditPermit`. Das verletzt Hard Rule 15.
- **Pfad:** frische Installation, die erste Zählung bringt keine Liste (`seedPending` bleibt
  gesetzt). `~restore-saf` → beim Zurückkommen stellt `onResume` den Refresh F auf `VersoApp.io`;
  das Lesen endet, `adoptRestored` stellt den Restore-Schritt R hinter F. F hat jetzt eine Liste,
  sein Hand-off läuft auf main vor Rs Rückmeldung, sät, und `save()` stellt S hinter R. R schreibt
  die wiederhergestellte Konfig, S schreibt die alte (leere + Standard-Favoriten) darüber;
  `adopt()` setzt nur den Speicher. Bis zur nächsten Änderung steht auf der Platte das Falsche —
  stirbt der Prozess vorher, ist der Restore weg. Plain `~restore` ebenso, wenn ein Refresh vor
  dem Schreibschritt wartet.
- **Vorbedingung:** eine erste Zählung ohne Liste — selten, aber genau der Fall, für den der
  Commit da ist.
- **Vorschlag:** säen nur, wenn `CommandGate` frei ist; sonst `seedPending` gesetzt lassen und
  beim nächsten Refresh erneut versuchen. Test in `LauncherStateTest` (Restore wartet, Hand-off
  mit Liste kommt dazwischen → nichts gespeichert, Wartezustand bleibt).

### 2. Neuaufbau mitten im Restore: Standard-Favoriten über eine Konfig ohne Favoriten — **mit #1 umsetzen** — ✅ `b270bab`
- **Stelle:** `LauncherState.kt:129-137` mit `adopt` (`:314-322`).
- **Pfad:** `seedPending` gesetzt, Rs Schreibschritt läuft, die Activity wird vor der Rückmeldung
  neu aufgebaut (Sprache, Dark Mode). `onUi` verwirft die Rückmeldung, `adopt()` läuft nie,
  `seedPending` (prozessweit) bleibt. Die neue Instanz lädt die wiederhergestellte Datei (nicht
  frisch), übernimmt `seedStillPending = true` und sät, wenn die Konfig keine Favoriten hat — gegen
  Hard Rule 10.
- **Vorschlag:** `seedPending` auf der IO-Seite löschen, sobald ein Restore erfolgreich geschrieben
  hat (im selben IO-Schritt wie das Schreiben, Hard Rule 7). Test: zwei Instanzen auf einem
  `ProcessState`, Rückmeldung der ersten verworfen.

## B. Tooling

### 6. detekt-Baseline verbucht die gewollten Catches als Altlast und deckt künftige mit — **umsetzen** — ✅ `4b415c5`
- **Stelle:** `app/detekt-baseline.xml`. detekt-IDs haben keine Zeilennummer:
  `TooGenericExceptionCaught:MainActivity.kt:MainActivity$e: RuntimeException` deckt drei Catches
  und jeden künftigen gleicher Art in der Datei. Ebenso `SwallowedException:…ConfigJson$e:
  Exception` usw. „Only ever shrinks“ hält damit keine neue Altlast auf.
- Zugleich Widerspruch zu CLAUDE.md: dort bekommt ein gewollter Fund ein schmales `@Suppress`
  („e.g. an IO path's broad catch (hard rule 2)“), die Baseline halte nur die Altlast. Die von Hard
  Rule 2 verlangten Catches (`Guard`, `ConfigStore`, `BackupStore`, `CommandGate`, `Apps`,
  `RecentsLog`, `UsageLog`) stehen aber als Altlast drin — wer sie „abbaut“, würde `Guard`s Catch
  verengen.
- **Vorschlag:** an jedem gewollten Catch `@Suppress("TooGenericExceptionCaught",
  "SwallowedException")` mit Grund, diese Einträge aus der Baseline. (Die Baseline stammt aus
  meinem Commit `760d7f1` — mein Versäumnis, sie ungesehen zu übernehmen.)

### 7. `PackageNaming` trifft jede Datei — **umsetzen** — ✅ `4b415c5`
- **Stelle:** 65 Einträge in `app/detekt-baseline.xml`. Das Paket `verso_launcher` ist fest
  (applicationId); jede neue `.kt`-Datei schlägt fehl oder lässt die Baseline wachsen.
- **Vorschlag:** in `config/detekt/detekt.yml` `naming: PackageNaming:` mit
  `packagePattern: '[a-z]+(\.[a-z][A-Za-z0-9_]*)*'` (oder abschalten), mit Grund; die Einträge

### 8. Lint-Baseline: `check` bricht ohne Codeänderung — **umsetzen** — ✅ `2c44a74`
- **Stelle:** `app/lint-baseline.xml`. `GradleDependency` (androidx.test runner) und
  `NewerVersionAvailable` (Robolectric) enthalten die neueste Upstream-Version im Text („…is
  available: 4.17“). Erscheint eine neue Version (oder eine für irgendeine andere Abhängigkeit),
  ändert sich der Text, und `lint` schlägt unter `warningsAsErrors` fehl. Die beiden toml-Einträge
  stehen zudem mit absolutem `$HOME/AndroidStudio_Projects/…`-Pfad drin (Zeilen 21, 43) —
  ein Checkout anderswo (Worktree, Cloud) passt womöglich nicht. Offline melden die beiden Checks
  gar nichts.
- `OldTargetApi` (targetSdk 36 ist Familienregel) und die Hochformat-Sperre
  (`LockedOrientationActivity`, `DiscouragedApi`) sind Entscheidungen, keine Altlast.
- **Vorschlag:** `lint { disable += setOf("GradleDependency", "NewerVersionAvailable",
  "OldTargetApi", …) }` mit Grund (bzw. die Orientierung per `tools:ignore` im Manifest); in der
  Baseline bleibt nur `SetTextI18n`.
